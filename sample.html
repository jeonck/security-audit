시험 대상 DVPWA · 정밀 점검 모드 · 약 28분
이 시험은 무엇인가요? 보안 점검 서비스가 실제로 문제를 찾아내는지 보여주려면 정답을 아는 문제가 필요합니다. DVPWA(Damn Vulnerable Python Web Application)는 보안 교육용으로 보안 구멍을 일부러 여러 개 만들어 둔 수강 관리 웹사이트이고, 어떤 구멍이 있는지 개발자가 미리 공개해 두었습니다. 그 공개된 5개를 정답지로 삼아, 우리 점검이 몇 개나 찾는지 그대로 공개합니다.
이 샘플의 수준: Scan (자동 점검 결과)AI 에이전트 34회가 6단계로 점검한 결과를 그대로 정리했습니다.
  • 포함: 자동 6단계 감사, 확정·추가 확인·기각 판정
  • 미포함: 담당자 직접 검토, 재현 절차 작성, 수정 후 재점검
Audit에서 추가되는 것같은 자동 점검 위에 사람이 더해집니다.
  • 보안 담당자가 모든 확정 항목을 직접 검토
  • 항목별 재현 경로와 따라 할 수 있는 수정 가이드

확실하게 확인된 문제 3건

▲ 위험 높음로그인 없이 입력창으로 데이터베이스를 조종할 수 있음기술 용어: SQL 인젝션

무슨 일이 생기나요? 누구나 글쓰기 칸에 특별한 문장을 넣는 것만으로, 저장된 모든 회원의 아이디와 비밀번호 정보를 화면에 불러올 수 있습니다. 로그인도 필요 없고, 요청 한 번이면 됩니다.

어떻게 고치나요? 입력값을 명령문과 분리해 처리하고, 이 기능에 로그인 확인을 추가합니다. sqli/dao/student.py:42

● 위험 중간남이 심어 둔 악성 글이 다른 방문자 화면에서 실행됨기술 용어: 저장형 XSS

무슨 일이 생기나요? 익명으로 쓴 글에 숨겨 둔 프로그램이, 그 글을 보는 방문자와 관리자의 브라우저에서 그대로 실행됩니다. 화면 조작, 가짜 로그인창 띄우기, 접속 정보 탈취에 쓰일 수 있습니다.

어떻게 고치나요? 글을 화면에 보여줄 때 자동으로 안전하게 변환하는 설정을 켭니다. sqli/app.py:35

● 위험 중간로그인 없이도 성적·과목·학생을 만들 수 있음기술 용어: 서버 측 권한 검사 누락

무슨 일이 생기나요? 화면에서는 관리자에게만 버튼이 보이지만, 서버는 누가 요청했는지 확인하지 않습니다. 버튼이 없어도 직접 요청을 보내면 성적을 입력할 수 있습니다. 건물 앞에 "직원 전용" 표지만 붙이고 문은 잠그지 않은 것과 같습니다.

어떻게 고치나요? 해당 기능마다 서버에서 관리자 여부를 확인합니다. sqli/views.py:52,84,135
